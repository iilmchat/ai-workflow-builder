### 3.2. Как снимались скриншоты

1. Собран `web/dist` в режиме Capacitor (`base: './'`).
2. Поднят статический сервер, Playwright открывает
   `http://127.0.0.1:4173/?workflowId=<uuid>[&runId=<uuid>]`.
3. **API замокан на уровне `page.route`** (реальный backend не поднимался):
   `POST /auth/refresh` (access-токен + пользователь), `GET /llm/models`,
   `GET /llm/health`, `GET /media/models` (`[]`), `GET /mcp/servers`
   (`enabled:false`), `GET /web-search/providers`,
   `GET /workflow/:id/document-templates` (`[]`), `GET /workflow/:id`,
   `GET /workflow/:id/runs`, `GET /runs/:id`, `GET /runs/:id/nodes`,
   `GET /runs/:id/budget`; неизвестные API-пути — 404 JSON, чтобы Zod не падал
   на HTML.
4. Фикстуры: граф «План запуска продукта» из 4 узлов (Текст → LLM →
   Генерация документа → Вывод), запуск `completed` со снимками узлов
   (182/214 токенов, `$0.000261`), история из 3 запусков
   (completed/failed/completed). Данные демонстрационные.
5. Пауза 4,2 с после загрузки — чтобы исчез toast «Workflow загружен»
   (`NOTICE_TIMEOUT_MS = 3000`).
6. **Viewport:** 1400×2489 CSS при `deviceScaleFactor: 0.7714` → PNG
   **1080×1920**. Причина: при 1080 CSS px шапка сжимает бейдж статуса и
   обрезает группу действий; при 1400 px всё влезает, а масштаб 0.7714 даёт
   ровно 1080×1920 физических пикселей (проверено).
7. **`04-mobile-qr.png`:** 540×960 CSS при `deviceScaleFactor: 2` → 1080×1920;
   перед загрузкой страницы выставлен `window.androidBridge = {}`, чтобы
   `Capacitor.isNativePlatform()` вернул `android` и в шапке появилась кнопка
   QR (она рендерится только в нативном режиме). Группа действий прокручена
   к кнопке QR (`scrollLeft`), т.к. в шапке она скроллится (KI-628).
8. **Иконка:** HTML-страница с фоном `#FEF3E7` и `logo.svg` на 72 % площади →
   screenshot 512×512 и 1024×1024.
9. **Баннер:** HTML + CSS-градиент, `logo-dark.svg`, Segoe UI, текст
   «AI Workflow Builder / Создай свой AI-сценарий / без кода · LLM · медиа ·
   агенты» → 1920×1080 и 1024×500.

### 3.3. Ограничения метода

- Скриншоты сняты из SPA-сборки в браузере, **не с Android-устройства**:
  Android-эмулятор в этой сессии не поднимался. Интерфейс тот же, но
  «нативность» QR-кадра — симуляция флага, а не реальный плагин.
- API замокан: цифры (токены, стоимость, даты) демонстрационные, не из
  реального запуска.
- Полноэкранный сканер QR (UI Google ML Kit) в кадр не попал — это системный
  интерфейс, запрещённый в скриншотах RuStore (п. 6.6).

## 5. Что не так

1. **B-1…B-7 в документе — реальные блокеры публикации, а не недочёты
   текста.** Главный: `API_BASE = ''` — release-AAB не достучится до
   backend; приложение не авторизуется на устройстве. Без закрытия B-1
   публикация бессмысленна.
2. **QR-сканер требует Google Play Services (B-7).** На устройствах без GMS
   (а это часть аудитории RuStore) кнопка «Сканировать QR» вернёт «недоступно»
   (WARN в консоли, для пользователя — ничего). В текстах QR заявлен как
   ключевая мобильная фича; до релиза нужен либо встроенный ML Kit, либо
   ограничение в описании.
3. **Push-уведомления не отправляются (B-2):** `sendToUserAsync` не вызывается
   ни из одного события. Тексты помечены «после закрытия B-2», но если релиз
   пойдёт раньше — пункт про push надо убрать.
4. **Скриншоты сняты не с устройства, а из SPA-сборки** с моками API; для
   публикации это приемлемо по содержанию, но при строгой проверке «кадры
   должны быть с приложения» лучше переснять на телефоне. `04-mobile-qr.png` —
   симуляция нативного режима (`androidBridge`), реальный сканер не показан.
5. **`04-mobile-qr.png` показывает только иконку кнопки QR** (подпись
   скрывается на узкой ширине) — если нужен явный текст «Сканировать QR»,
   снимать на реальном устройстве с нативной подписью.
6. **Иконка лаунчера в APK не заменена (B-4):** брендовый `icon-512x512.png`
   готов, но mipmap-ресурсы в `web/android/app/src/main/res` остались
   стандартными (синяя «X» Capacitor). Иконка карточки и приложения не совпадут.
7. **В манифесте лишние разрешения (B-5):** `READ_MEDIA_IMAGES` /
   `READ_EXTERNAL_STORAGE` не используются — риск расширенной проверки.
8. **`minSdkVersion = 23`** при ориентире RuStore на Android 8.0+ (B-6) —
   вопрос модератору почти гарантирован.
9. **Нет удаления аккаунта и согласия на ПД (B-3)** — прямое нарушение п. 5.4
   и риск по ФЗ-152.
10. **Данные на скриншотах демонстрационные** (мок-API): реальные названия
    сценариев/цифры при пересъёмке на устройстве будут другими.
11. **Новые KI не заведены в `docs/KNOWN_ISSUES.md`**: пакет выполнялся без
    коммитов, реестр не трогался. Дефекты перечислены в § 6 — их нужно
    завести отдельным docs-пакетом (с пересчётом сводки по RULES 3.20).
12. **Политика конфиденциальности, согласие и Terms отсутствуют как документы**:
    `RUSTORE_PUBLISH.md` описывает, что в них должно быть, но самих текстов в
    репозитории нет — это юридическая задача, вне S5-A. Без неё п. 5.1 RuStore
    не закрыть.

## 7. Обоснование решений

1. **Почему 1400×2489 CSS → 1080×1920, а не 1080×1920 CSS @2.** При 1080 CSS
   px шапка (`TopBar`) не помещается: бейдж статуса сжимается до «Завер…», а
   группа действий прокручивается — скриншот выглядел бы как баг. При 1400 CSS
   px всё влезает; `deviceScaleFactor 0.7714` даёт ровно 1080×1920 физических
   пикселей — итоговый файл соответствует ТЗ и лимитам RuStore.
2. **Почему 4 скриншота, а не 8.** ТЗ S5-A требует 4 кадра (холст, результат,
   история, мобильный QR). RuStore требует минимум 3 — набор закрыт; остальные
   (шаблоны, сравнение, каталог) перечислены в § 3.3 документа как опция для
   ручной съёмки.
3. **Почему моки API, а не реальный backend.** Для скриншотов нужен backend с
   PostgreSQL/Redis и seed-данными, а также ключи LLM-провайдеров; это вне
   S5-A. `page.route` даёт детерминированные данные и не требует секретов.
   Данные помечены как демонстрационные (§ 3.3, § 5).
4. **Почему PNG, а не JPG.** UI-скриншоты с плоскими цветами лучше сжимаются
   без артефактов; PNG-файлы 98–130 КБ, лимит 3 МБ не близко. Иконка — PNG
   без прозрачности (требование RuStore).
5. **Почему иконка на фоне `#FEF3E7`.** Логотип чёрный; фирменный светлый фон
   (`logo-dark.svg` использует `#fef3e7`) даёт контраст и заполнение по всей
   площади без прозрачных краёв.
6. **Почему два размера баннера.** 1920×1080 — универсальный 16:9 для промо;
   1024×500 — распространённый размер обложек (VK/статьи). В карточку RuStore
   баннер не загружается — поля нет; это зафиксировано в документе и отчёте.
7. **Почему `window.androidBridge` для 4-го кадра.** Кнопка QR рендерится
   только при `isNative()`. Реального Android-устройства в сессии нет, поэтому
   нативный режим симулирован флагом Capacitor; это единственный способ
   показать кнопку без кода. Ограничение честно указано (§ 3.3, § 5).
8. **Почему временные скрипты вне репозитория.** RULES 3.13 требует удалить
   временные скрипты; размещение в `%TEMP%` гарантирует, что в `git status` не
   появится мусор, а после прогона каталог удалён. В отчёте сохранены команды и
   параметры для воспроизведения.
9. **Почему документ переписан в v1.1, а не пропатчен точечно.** Корректор
   вернул 34 правки (факты, формулировки, названия пунктов Консоли, блокер
   B-7); точечные замены в 555-строчном файле дали бы рассинхрон нумерации и
   длин текстов. Переписывание с пересчётом длин (64/3181/421) дало
   консистентный документ.
10. **Почему KI не заведены в KNOWN_ISSUES, но CHANGELOG обновлён.** CHANGELOG —
    обязательная запись о пакете (RULES 2.18), она точечная и не требует
    пересчёта сводок. Заведение 6 новых KI требует правки реестра и пересчёта
    сводки по RULES 3.20/3.21 — отдельный docs-шаг; в этой сессии дефекты
    зафиксированы в § 6 отчёта, чтобы не сломать реестр «наполовину».
