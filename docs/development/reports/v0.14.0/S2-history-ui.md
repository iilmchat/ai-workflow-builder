## 3. Диагностика

### 3.1 Смоук в реальном браузере (а не только jsdom)

Компонентные тесты в jsdom не доказывают, что модалка открывается в живом
приложении: нужен dev-сервер, прокси Vite, настоящая JWT-сессия и реальные
данные из PostgreSQL. Подняли backend (`node dist/main`, `AUTH_DISABLED=false`),
Vite dev (`127.0.0.1:5173`), зарегистрировали пользователя, создали workflow,
вставили 3 запуска (completed/failed/pending) и прошли путь браузером через
Chrome DevTools Protocol: `--headless=new --remote-debugging-port=9222`,
управление по WebSocket (Node 24, без puppeteer). Это дало настоящий
`innerText`, порядок строк, состояния disabled и скриншоты — см. § 4.

### 3.2 Ловушка Prettier: `--write` переформатировал чужие строки

Проверка `prettier --check` на файлах из `.smoke/` показывала «clean», но это
был ложный сигнал (файлы не те, что правятся). После `prettier --write` по
`TopBar.tsx`/`api.ts`/`api.spec.ts` выяснилось, что кодовые файлы в репозитории
на HEAD **не полностью prettier-clean** (форматирование по умолчанию
переписывает десятки посторонних строк). Такие правки — шум в diff'е и нарушение
«1 шаг = 1 изменение», поэтому reformat откатил (`git checkout -- <файлы>`) и
заново внёс только смысловые изменения; diff снова содержит только фичу.
Формат-гейта в CI нет (prettier запускается husky на commit, которого в сессии
нет).

### 3.3 Округление длительности: «1 мин 60 с»

Версия форматтера наивно округляла секунды: `119500 мс` → `1 мин 60 с`,
`59999 мс` → `60.0 с`. Исправлено порогом `59.95 с` и переносом «60 секунд» в
минуту (`seconds === 60 → minutes + 1, seconds = 0`). Границы закреплены тестом:
59.999 с → `1 мин 0 с`, 119.5 с → `2 мин 0 с`, строки «60.0 с»/«1 мин 60 с»
отсутствуют.

### 3.4 `?runId=` и F5 после клика по истории

Сначала клик писал `?runId=` в адрес (казалось логичным для F5, KI-271). Но
`restoreRunAsync` для завершённого запуска **удаляет** параметр («подписываться
не на что»), т.е. запись была бы мгновенно стёрта и F5 всё равно не восстановил
бы панель, а тест с замоканным `restoreRunAsync` это скрывал бы. Запись убрана,
ограничение зафиксировано как KI-541 с честным описанием: F5 после любого
клика из истории теряет панель (для `pending`/`running` — тоже, параметра нет).

### 3.5 Пагинация и её границы

`totalPages = max(1, ceil(total / 20))`, `currentPage = min(totalPages,
floor(offset / 20) + 1)`; «Назад» активна при `offset > 0`, «Вперёд» — при
`offset + 20 < total`. Проверено для `total = 0/20/21/45` и `offset =
0/20/40/60` (логика + тесты): off-by-one нет, на последней странице «Вперёд»
выключена, пустая история — «Страница 1 из 1». `total` берётся из ответа
backend (S1), а не из длины массива — иначе счётчик страниц врал бы.

### 3.6 Дубли KI-537..540 в HEAD

В `docs/KNOWN_ISSUES.md` на HEAD оказались **две копии** записей KI-537..540
(подробные + краткие, с одинаковыми номерами). При добавлении KI-541..545
краткий дублирующий блок удалён, оставлены подробные версии (имена, файлы,
решения). Это объясняет −25 строк в diff'е реестра. Найдено при аудите перед
добавлением новых KI.

### 3.7 Расхождение подписи статуса (найдено смоуком)

CDP-смоук показал: после клика по завершённому запуску панель результата
пишет «Запуск · завершён», а кнопка Run в TopBar — «Готово». Поведение верное,
расходится текст (панель использует узельные подписи `run.status.node.*`).
Записано как KI-545 (Documented), в этом срезе не правилось, чтобы не менять
i18n вне scope.

### 3.8 jsdom vs браузер в тестах

`RunHistoryModal.spec.tsx` использует глобальный i18n из `test/setup.ts`
(`localStorage.lang = 'ru'`), поэтому проверяются реальные подписи, а не ключи.
Даты сравниваются через тот же `toLocaleString('ru-RU')`, что и компонент, —
тест не зависит от таймзоны CI. После замечаний verifier'а добавлены проверки
`durationMs = null` («—»), нулевой стоимости (`$0.0000`), точной даты, границы
последней страницы, закрытия по фону/✕ и порядка вызовов
(`onClose` → `setSelectedNodeId(null)` → `restoreRunAsync`).

## 5. Что не так

1. **KI-541 (🟢 Low):** F5 после клика по запуску из истории не восстанавливает
   панель — `restoreRunAsync` не пишет `?runId=`, а для завершённого запуска
   ещё и удаляет его (KI-271). Требует решения в S3.
2. **KI-542 (🟡 Medium):** offset-пагинация истории сдвигается при появлении
   новых запусков (возможны дубли/пропуски). Нужен keyset-курсор в API
   (связано с KI-540 — индексом под `(created_at, id)`).
3. **KI-543 (🟢 Low):** открытая модалка не обновляется в реальном времени:
   статусы `pending`/`running` и новые запуски не подтягиваются до
   переоткрытия/перелистывания.
4. **KI-544 (🟢 Low, Documented):** в списке нет причины падения (`error` не
   входит в `RunSummary` S1): failed-строка — просто «Ошибка», причина видна
   только после клика.
5. **KI-545 (🟢 Low, Documented):** статус `completed` называется «Готово» в
   TopBar, «завершён» в панели результата и «Завершён» в истории — расхождение
   i18n-подписей, найдено CDP-смоуком.
6. **`viewer` не видит историю:** backend-ручка требует `editor` (S1/KI-537),
   поэтому кнопка для `viewer` скрыта. Это следствие KI-537, а не новый дефект;
   при ослаблении проверки до `viewer` кнопку нужно вернуть.
7. **В HEAD были дубли KI-537..540** (две копии с одинаковыми номерами). В S2
   удалён краткий дубль, оставлены подробные записи; реестр стал однозначным.
8. **Тесты модалки используют русские литералы** (`'Завершён'`, `'2.0 с'`):
   язык зафиксирован в `setup.ts`, но при правке копирайта тесты придётся
   обновить. Осознанно: проверяется фактическая подпись, а не ключ; verifier
   отметил это как nit.
9. **`pnpm lint` — 2 warning'а** в
   `src/media/providers/openai-images.provider.spec.ts` (не трогали; на HEAD те
   же). Отдельного линта web в репозитории нет.
10. **Toast «Workflow загружен…» перекрывает модалку** (z-50 > z-40) — так
    задумано (уведомления должны быть видны), но выглядит наложением; при
    желании Toast можно приглушать при открытой модалке.
11. **Смоук требует локальных backend+Vite+PostgreSQL** и запускается вручную
    (артефакт в `.smoke/`), в CI не входит — это dev-проверка, а не e2e-гейт.

## 7. Обоснование решений

### 7.1 Локальное состояние TopBar, а не поле в сторе

Задача допускала `isHistoryModalOpen` в сторе или локальный стейт. Выбрал
локальный: так же открываются `LoadModal` и `ShareModal`, а само открытие
модалки никому, кроме TopBar, не нужно — в стор попадает только результат
(через `restoreRunAsync`). Стор остался без изменений: меньше поверхности и
никаких `reset`-обязанностей для UI-флага.

### 7.2 Модалка, а не отдельная страница

История — способ открыть прошлый результат, не уходя с холста: модалка
сохраняет граф, незакоммиченные правки и текущую сессию. Отдельный роут
потребовал бы загрузки workflow по `?workflowId=` и синхронизации состояния —
это S2-скоуп раздуло бы (в DESIGN § 3.2 явно «модальное окно (или страница)»).

### 7.3 Список кнопок, а не `<table>`

Каждая строка — `<button>`, вся строка доступна с клавиатуры (Tab + Enter) и
имеет `aria-label` «Открыть запуск {id}»; `<tr onClick>` пришлось бы отдельно
доводить до доступности (role/tabIndex/клавиши). Заголовки колонок вынесены в
отдельную grid-строку — визуально таблица, семантически — список действий.

### 7.4 Статус-метаданные локально в модалке

`HISTORY_STATUS_META` (иконка/цвет/ключ) задана в `RunHistoryModal`, а не
переиспользована из TopBar: в TopBar подписи — `run.status.*` («Готово»,
«Создаётся…»), в истории нужны короткие `history.status.*` («Завершён»,
«Ожидает»). Общий модуль связал бы две разные копии ради 5 строк. Расхождение
формулировок с панелью результата зафиксировано как KI-545.

### 7.5 `fetchWorkflowRunsAsync` — в `api.ts`, а не inline в компоненте

Все REST-вызовы живут в `api.ts` рядом со своими Zod-схемами; компонент не
должен знать про URL и разбор. Функция — тонкая обёртка, поэтому её легко
проверить отдельно (`api.spec.ts`: URL с дефолтами/явными значениями, отказ
Zod на битом ответе).

### 7.6 Форматирование стоимости и длительности

Длительность: `< 1 с` — миллисекунды, `< 60 с` — секунды с одним знаком,
дальше минуты+секунды; `null` — «—» (запуск не завершён). Стоимость: USD с
4 знаками (доли цента), RUB с 2 (копейки), нулевая валюта не печатается,
полный ноль — `$0.0000`. Смешивать валюты в одну нельзя (RULES 4.23), поэтому
показываем обе через «+».

### 7.7 Клик: сначала закрыть, затем восстановить

Порядок из задачи — «закрой модалку, загрузи `restoreRunAsync`, открой панель».
Панель результата в `App` смонтирована всегда (это футер-панель, не модалка),
поэтому «открыть» = заполнить её данными выбранного запуска. `selectedNodeId`
сбрасывается до вызова: иначе панель показала бы узел предыдущего запуска
(стор намеренно не сбрасывает выбор при старте нового прогона). Порядок
закреплён тестом через `invocationCallOrder`.

### 7.8 Пагинация «Назад/Вперёд», а не «Показать ещё»

Классическая страничная навигация даёт пользователю контроль и не растягивает
DOM; «Показать ещё» накапливало бы строки и требовало отдельного состояния.
Предел `limit=100` и права проверяет backend (S1), UI использует `PAGE_SIZE=20`
и блокирует кнопки на границах.

### 7.9 Тесты: поведение, а не снимки

Проверяются реальные сценарии: рендер данных (включая null/0), смена `offset`
по клику, граница последней страницы, ошибка+retry, три способа закрытия,
порядок действий при выборе запуска. API-мок поднимается через `importOriginal`
(остальные функции `api.ts` настоящие) и сбрасывается в `afterEach`; файлы
vitest изолированы, утечки между спеками нет.

### 7.10 Смоук — настоящий браузер, но с честными оговорками

CDP-смоук даёт то, чего jsdom не даёт: dev-прокси, реальная JWT-сессия,
настоящий рендер Tailwind и `innerText` строк. Ограничения (одна страница
пагинации, данные в БД вставлены напрямую) описаны в § 4, а не выданы за
полное e2e-покрытие. Скрипт и скриншоты — gitignored артефакты, чтобы не
тащить в репозиторий окружение Chrome/БД.

### 7.11 Процесс

Ни одного `git add`/`git commit` не выполнено (жёсткое правило задачи).
Правки форматирования, случайно затронувшие чужие строки, откачены
(`git checkout --`) и внесены заново — итоговый diff содержит только фичу
(§ 3.2). Код и тесты проверены независимым verifier-агентом (PASS WITH NITS:
округление длительности, покрытие тестов, формулировки KI — исправлено до
итогового прогона) и CDP-смоуком (51/51). Финальные гейты перепроверены Лидом
(§ 2).
