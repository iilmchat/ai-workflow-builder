## 3. Диагностика

- **KI-027** подтверждён полностью: `createRunAsync` писал `inputs: {}`,
  `RunsProcessor` не читал колонку, движок не принимал входы.
- **KI-026** устарел: отмена (`POST /runs/:id/cancel`, `cancelled_at`,
  `RunCancelledException`) реализована в v1.4.0 S1, таймауты HTTP/аренды есть.
  Прокидывание единого `AbortSignal` в LLM-провайдеры не нужно при текущей
  модели прерывания через флаг в БД.
- **KI-033** частично закрыт KI-301 (type-aware резолвер); оставшаяся часть
  (явный неизвестный хэндл → дефолт) — осознанный fallback KI-030.
- **KI-035** не может быть закрыт как описано без изменения исполнителя:
  `llm` читает только `inputs.prompt`, разложение по `targetHandle` сделает
  входы невидимыми.

## 4. Smoke

Три новых теста: (1) источник графа получает `{ prompt, limit }` из
`runInputs`, узел со входящей связью — только выходы предшественника;
(2) `createRunAsync` сохраняет переданные `inputs`; (3) `RunsProcessor`
передаёт `inputs` в `executeAsync` после Zod-проверки. Существующие 6 ожиданий
вызова `executeAsync` обновлены под новую сигнатуру (третий аргумент `{}`).

## 5. Что не так

- `runInputs` подмешиваются только в узлы без входящих рёбер; узел со связями
  не видит run-вход — это выбранная семантика (приоритет явных связей).
- Размер `inputs` ограничен только длиной ключа (128), не числом байт значения;
  1 МБ не гарантирован. Для публичного контракта можно добавить лимит
  сериализованного JSON (отдельный KI при необходимости).
- В подграфах run-входы не действуют — входы идут по рёбрам родителя.

## 6. Новые KI

Не заведено: ограничения выше — границы выбранного контракта, а не регрессы.

## 7. Обоснование решений

- **Ключи `inputs` как имя порта:** это позволяет источнику (`text`, `http`,
  `llm`) получить значение без правки executor'ов — они уже читают `inputs`.
- **Только источники:** если подмешивать во все узлы, run-вход молча
  перекрывал бы явные связи и делал граф недетерминированным.
- **Won't Fix для KI-033/035:** обе «правки» ухудшают функционал (ломают старые
  графы или делают входы невидимыми). Вместо них корректные механизмы уже
  существуют: KI-301 (type-aware порты) и `merge`-узел (KI-194).
