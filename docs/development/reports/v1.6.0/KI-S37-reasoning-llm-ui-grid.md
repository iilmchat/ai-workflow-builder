## 3. Диагностика

- **KI-249:** оказалось не только дублированием. Backend-тип `ReasoningEffort`
  после KI-246 содержит шесть значений (`off`, `minimal`, `low`, `medium`,
  `high`, `xhigh`), а фронт знал три. `validateReasoningEffort()` возвращал
  `undefined` для `minimal`/`low`/`xhigh`, то есть при Load графа из БД
  сохранённый режим молча терялся, а следующий Save затирал его. Третья копия
  union в `types/graph.ts` не была связана с рантайм-валидацией вообще.
- **KI-250:** при известном `defaultMaxTokens` плейсхолдер был голым числом
  (`4096`); общий ключ i18n «По умолчанию» использовался только когда дефолт
  неизвестен. Просто заменить ключ шаблоном с `{{value}}` нельзя — для модели
  без дефолта он рендерился бы как «По умолчанию: ».
- **KI-251:** маппинг LLM-полей покрывался только CDP-смоуком; инфраструктура
  тестов web с jsdom и алиасом `@/` (KI-155) уже была, отдельного specs не было.
- **KI-252:** `SNAP_GRID = [8, 8]` жил локальной константой `Canvas.tsx` и
  влиял только на `snapToGrid` React Flow при drag; `addNode` получал дробный
  центр вьюпорта из `findCenter`, `addNodeOnEdge` — дробный центр связи из
  `insertPositionOnEdge`.

## 4. Smoke

- **Паритет reasoning:** новый spec читает оба исходника как текст (пути от
  `import.meta.url`, а не `process.cwd()`), извлекает литералы из
  `export type ReasoningEffort = …` и `export const REASONING_EFFORTS = […] as const`
  и сравнивает отсортированные списки. При переименовании/изменении формата
  объявления бросается ошибка с именем файла — ложного зелёного на пустом
  списке нет. Тест зелёной на 6 значениях с обеих сторон.
- **UI reasoning:** селект строится из `REASONING_EFFORTS`, поэтому появление
  нового режима на бэке без перевода в i18n упадёт в тесте i18n-паритета,
  а не останется ключом-сылкой. Проверены ключи `node.llm.reasoning.{minimal,
  low,xhigh}` в `ru.json` и `en.json` (RULES 1.14).
- **Плейсхолдер:** `node.llm.maxTokens.placeholder` = «По умолчанию: {{value}}»
  / «Default: {{value}}»; при отсутствии `defaultMaxTokens` используется
  новый `placeholderGeneric` («По умолчанию» / «Default»). Сборка web 0/0,
  i18n-тесты в составе 607 зелёных.
- **Load LLM:** три теста через `loadWorkflowAsync` (мок `getWorkflowAsync`)
  проверяют перенос всех полей, все шесть режимов по очереди и отброс мусора
  (`model: 42`, `systemPrompt: 7`, `reasoningEffort: 'ultra'`,
  `maxTokensOverride: -1`) с fallback старого `value` в `prompt`.
- **Сетка:** `snapToGridPosition({x:13,y:200.5})` → `{x:16,y:200}`, нулевые и
  уже выровненные позиции не меняются. Стор: узел из Toolbar `{13, 200.5}`
  встаёт в `{16, 200}`; узел, вставленный в связь между узлами с дробными
  координатами, имеет `x % 8 === 0` и `y % 8 === 0`.
- **Реестр:** `node scripts/check-known-issues.mjs` — OK; сводка пересчитана
  grep'ом до и после правки: Fixed 354 (350 + 4), Open 124 (128 − 4),
  итого 657, уникальных номеров 657.

## 5. Что не так

- KI-246 был закрыт на бэке, но UI так и не показал новые режимы — фактически
  фикс был наполовину. Спринт 37 закрывает этот остаток, не открывая новый KI.
- Паритет-тест написан на регулярках по исходникам: при переносе объявления в
  другой файл или изменение формата придётся править сам spec (но он упадёт,
  а не промолчит).
  Перенос канонического списка в общий JSON-контракт — отдельная задача по
  образцу `api-contract.json`, в этом спринте не делалась.
- `minimal`/`low`/`xhigh` доступны в UI для любой модели с `supportsReasoning`:
  backend пропускает значение дальше провайдеру, который может не поддержать
  конкретный режим. Это поведение унаследовано от KI-246, в спринте не менялось.
- В `docs/KNOWN_ISSUES.md` есть исторические заметки S7/S8 со старыми счётчиками
  (`Fixed 294/297/300/302`) — это архивная хроника, в спринте не переписывалась;
  актуальная сводка — в конце секции «Сводка по статусам».
- `pnpm lint` выдаёт 2 pre-existing warning'а `no-base-to-string` в
  `src/media/providers/openai-images.provider.spec.ts` (строки 567/588) — до
  спринта 37, к изменённым файлам отношения не имеют; `pnpm build` — 0/0.
- CDP-смоук в браузере не проводился: изменения детерминированы и покрыты
  юнит-тестами+паритет-гейтом; визуальная проверка новых опций селекта и
  подписи плейсхолдера — при следующем ручном прогоне UI.

  с новым дублем константы.
