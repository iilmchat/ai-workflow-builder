## 3. Диагностика

- **KI-359:** тип финального статуса дублировался литералами в трёх местах,
  канон (`TERMINAL_WORKFLOW_RUN_STATUSES`) был только в `db/schema.ts`.
- **KI-355/358/360:** продуктовый выбор (консистентность важнее экономии),
  AST-гейт вместо Zod и перспектива vector store — не дефекты кода.
- **KI-374:** дефолтный промпт для `bgremover` уже подставляется в image-tool.
- **KI-375:** бюджетный бар скрывался сразу после финала, хотя последний
  снимок оставался в сторе.
- **KI-376/388:** отдельный REST-запрос бюджета вызывается только при
  подключении; DESIGN § 3.2 уже отражает каталог, автоподстановка модели
  сделана в S31.
- **KI-389/395:** плейсхолдер голоса обещал вымышленный id, `speed` не
  объявлен ни одной моделью; allowlist песочницы в DESIGN отставал от кода.
- **KI-394/396:** операционная процедура и инфраструктура без изменений кода.

## 7. Обоснование решений

- Канонический тип статуса взят из `db/schema.ts`: переименование статуса
  теперь подсвечивается компилятором во всех потребителях.
- Там, где исправление означало смену продуктового решения или контракта
  (early-abort, Zod-гейт REST, SSE-budget, catalog голосов), выбран status
  `Documented` с явным триггером возврата — это честнее, чем фиктивный «fix».
- Изменения UX (бюджет после финала, плейсхолдер TTS) минимальны и не трогают
  контракты API.
- Документация DESIGN/RELEASES/SMOKE_CDP приведена к факту кода и окружения,
  чтобы следующая сессия не переоткрывала те же KI.
- Отчёт — один на три спринта по указанию пользователя; docs обновлены в этом
  же коммите (RULES 2.1/2.12/3.17).
