## 3. Диагностика

- **KI-533:** глобальный allowlist означал, что каждый stdio-процесс получал
  все разрешённые переменные backend'а — лишние секреты уходили сторонним
  процессам.
- **KI-537:** UI уже скрыл «Историю» для viewer, но backend-ручка осталась
  editor-only; нужно продуктовое решение.
- **KI-538:** денормализация стоимости запуска требует миграции и backfill.
- **KI-661:** удаление аккаунта — отдельный срез S6 с юридическим документом.

## 4. Smoke

Тест: два stdio-сервера с `envAllowlist: ['MCP_A']` и `['MCP_B']` при
глобальном `MCP_A, MCP_B` получили ровно по одной своей переменной. Старые
тесты глобального allowlist проходят без изменений.

## 5. Что не так

- Серверы без `envAllowlist` по-прежнему используют глобальный список —
  обратная совместимость, но оператору нужно явно развести секреты по серверам.
- KI-537/538/661 отложены с триггерами возврата.

## 6. Новые KI

Не найдено.

## 7. Обоснование решений

Per-server список — сужение, а не замена глобального: старые конфигурации
работают, а безопасность повышается там, где оператор явно разделил env.
Проверка остаётся на границе сборки env дочернего процесса.
