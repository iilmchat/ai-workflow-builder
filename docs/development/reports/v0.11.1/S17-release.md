## 3. Диагностика

1. **В рабочем дереве была ошибочная незакоммиченная правка KI-381.**
   KI-381 («нет серверной идемпотентности у Replicate/FAL/OpenAI») был помечен
   `Fixed` в v0.11.1 (S2), хотя S2 добавил только клиентскую карту в памяти —
   ровно то, что KI-381 и описывает как недостаточное. Статус возвращён в
   `Open`; этим объясняется промежуточное расхождение: при ошибочной правке
   фактические были Fixed 230 / Open 269, а сводка — 229/270.
2. **Сводка KI пересчитана grep'ом (RULES § 3.20):** 513 заголовков `### KI-`
   = 513 статусов; Fixed 229 (включая «Fixed (частично)»), Open 270,
   Documented 8, Planned 1, Deferred 1, Won't Fix 4. Открытых High — **0**.
3. **`pnpm --dir web build` ранее печатал предупреждение Vite** о JSON-import
   без import attributes (`api-prefixes.json`). Для требования «0/0» импорт
   переведён на `with { type: 'json' }`; повторная сборка — без предупреждений.
4. **Полные прогоны прошли с первого раза.** 18 skipped — это интеграционные
   тесты, которым нужны живая БД, ключи провайдеров или внешняя сеть; они
   штатно пропускаются и в CI (RULES § 3.19).
5. **`pnpm build` в pnpm 12 сначала выполняет install/prepare** (Husky), затем
   `nest build`; это не ошибка, итоговый код — 0.

## 5. Что не так

1. **`PROMPT_CURRENT.md` остаётся устаревшим** (в нём S9, 1359/395, KI-496,
   3 Open High). Это не входило в задачи S17 и уже отслеживается KI-522
   (промпт ссылается на устаревшие точки правки) и KI-498 (дублирование
   метрик). Перед следующей правкой системных инструкций его нужно
   синхронизировать по RULES § 2.17.
2. **18 backend-тестов пропущены** (DB/сеть/ключи). Это ожидаемо локально, но
   означает, что полный паритет с CI достигается только в CI с сервисами.
3. **`KI-525` (Medium, Open)** — остаточный DNS rebinding при скачивании входа
   OpenAI Images. Не блокирует патч-релиз, но требует бинарного метода в
   `SafeHttpClient`.
4. **Исторические упоминания v0.11.0 в USER_GUIDE/QA сохранены** намеренно:
   они описывают, когда фича появилась. Версия продукта при этом обновлена на
   0.11.1.
5. **В CHANGELOG нет compare-ссылок** между версиями — это существующий стиль
   файла, не регрессия S17.
6. **Коммит и тег не создавались** по жёсткому правилу промпта; релизный тег
   должен выставить пользователь после проверки.

## 7. Обоснование решений

1. **Почему `0.11.1`, а не `0.12.0`.** В патче только исправления и
   совместимые улучшения: отключение внутренних ретраев SDK (KI-500),
   скрытие неработающей операции (KI-418) и реализация уже обещанного
   `applyToolAsync` (KI-380). Новых публичных контрактов нет — SemVer требует
   patch.
2. **Почему `[Unreleased]` переименован, а не удалён.** RULES § 2.2: рабочая
   секция должна остаться пустой сверху, а всё содержимое — перейти в
   `[0.11.1] — 2026-10-19`. Содержимое `Fixed` сохранено дословно.
3. **Почему метрики взяты из прогонов, а не из README.** README содержал
   старые 1424/417. Цифры 1439/419 получены фактическим запуском
   `pnpm test` и `pnpm --dir web test`; 513 записей / 0 Open High — grep'ом по
   реестру (RULES § 3.20, 3.21).
4. **Почему обновлены USER_GUIDE, QA и RELEASES сверх списка задачи.**
   RULES § 2.16 требует актуализировать гайды перед каждым релизом, а
   `RELEASES.md` — источник ожидаемых цифр для приёмки. Без этого релизный
   docs-гейт формально не закрыт.
5. **Почему исправлен JSON-import.** Требование «`pnpm --dir web build` 0/0»
   несовместимо с предупреждением Vite. `with { type: 'json' }` — штатное
   исправление, а не подавление через env.
6. **Почему KI-381 возвращён в `Open`.** Статус `Fixed` без серверной
   идемпотентности (Redis/БД) вводил бы в заблуждение: S2 по-прежнему хранит
   карту в памяти, а KI-381 описывает именно этот недостаток. Ложное закрытие
   хуже открытого техдолга.
7. **Почему не добавлены новые KI.** Все обнаруженные расхождения либо уже
   покрыты (KI-522, KI-498, KI-525), либо являются ожидаемыми ограничениями
   прогона (skipped-тесты). Дублировать записи — нарушать RULES § 3.20.
8. **Почему не создан тег.** Промпт запрещает коммит; тег без коммита
   невозможен. Версии и CHANGELOG подготовлены, финальный `git tag v0.11.1`
   остаётся за пользователем.
